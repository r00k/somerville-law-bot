## Addressed in this commit

### 1. Verifier dropped true quotes over pre-punctuation spaces (launch finding #1, was incompletely fixed)

The launch-review fix normalized whitespace runs but not the corpus's
OCR-style spaces *before* punctuation ("Building Official .", "System .",
"District ."). All 3 real dropped citations this window were this false
negative — a well-supported B&B claim on the Airbnb answer (zon:705), the MS4
rule on sump-pump (coo:952), and the certificate-of-occupancy rule on
coworking (zon:874). Each was confirmed to match once `\s+([.,;:!?])` → `\1`
is applied. **Fixed** in `_normalize` (app/agent.py) with a regression test;
all three prod quotes now verify.

### 2. Sump-pump question missed Sec. 12-2 twice

Two askers (7/30) were told the code "doesn't directly address" pump water
flowing across sidewalks/streets — but Sec. 12-2(b) prohibits exactly that
("no person using water … for other purposes shall … allow it … to flow or
collect upon any street, or to flow upon or across the surface of any
sidewalk"). One answer also misattributed the neighbor-runoff rule to
Sec. 11-145, which only governs impervious-surface *construction*. Verbatim
verification can't catch real-quote-wrong-rule attribution. **Fixed** by
adding a `sump-pumps-drainage` wiki page routing sump pump / drainage
vocabulary to Sec. 12-2 + 11-165 + 11-145 + 11-176.

## Still open

### 3. Citation schema pressure produces junk citations (launch finding #3, recurring)

- "What is a home rule petition?" emitted a second citation whose quote was
  the literal string `"placeholder"` (verifier dropped it; the real citation
  to the same section survived).
- "Hey, it's Elena" (a greeting, not a question) got a correct friendly
  redirect — but with an irrelevant Sec. 1-1 citation attached, an artifact of
  the pipeline wanting at least one citation.

Cheap insurance: a degenerate-quote lint (`placeholder`/`TODO`/very short
quotes) — a stub that happened to match corpus text would sail through today.
The bigger fix remains an explicit out-of-scope/no-claims response shape that
legitimately carries zero citations.

### 4. Markup leakage

A literal `</caveats>` tag appeared in one rendered answer (coworking
follow-up, request `1d112bf2cbec`). The caveats-extraction path can leak the
closing tag into answer text.

### 5. Animal answers under-cite the zoning layer

Both chicken answers nailed the Board of Health regs (coo:2180) item-for-item
but omitted the citywide zoning aviculture standards (§9.2.14.c.ii) — notably
the **no hens within 20 feet of a front lot line** siting rule and the
resident-ownership requirement. Worth adding to the `animals-chickens` wiki
page.

### 6. Over-generalized qualifiers when compressing multi-clause provisions

A mild recurring pattern; bottom lines stayed right but scope details drifted:

- Ethics committee: the one-year post-service tail in Sec. 15-32(e) attaches
  only to (e)(1) (holding/running for office), but the answer applied it to
  all three (e) restrictions.
- Leaf blower: conflated the OLP path (2+ acres, plan-approved → exempt from
  the seasonal window, 9-120(b)(3)) with commercial operators (plan-approved
  but still bound by (b)(1)–(2) — never exempt from the season).
- "Administrative code": silently equated it with the Code of Ordinances; the
  2012 charter amendment's separate Administrative Code (referenced in the
  ordinance table) isn't in the corpus and the ambiguity went unflagged.

### 7. Users bail during long answers

All 3 empty answers were client disconnects during research (including one
person's only visit, on the elections commission). Median 20s / p90 45s is a
long wait; the disconnects are the closest thing to negative feedback this
window (the feedback buttons went unclicked).
